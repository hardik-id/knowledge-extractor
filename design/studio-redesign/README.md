# Knowledge Studio redesign (approved 2026-11-22, working screen revised the same day)

One working screen for a Studio project: the document with what was found in it on the left, the configuration (the prompt, the field table, the assistant) on the right. Define and Review stop being separate tabs.

Revision: the product owner kept the field table with its "Exact quote" and "Several values" checkboxes, and does not want values repeated on the right. Points 3 to 6 below are the revised ones; `Main.dc.html` shows them, except the record strip (point 4), which was revised again on 2026-11-22 after use: it now shows the whole record, and the mock-up still draws the older strip.

## The design

1. **No left sidebar on project screens.** One top bar, about 48px: the logo, a "Projects" link, "/", the project name (a menu: rename, edit description, delete), a document switcher (the file name, "n of N", previous and next), a "Document | Output" switch, then on the right the version text, "Assistant", one orange Run button, a "more" menu, the theme toggle and the account menu.
2. **The document switcher** lists the project's documents with their state ("3 to review", "3 records reviewed" when none is left to review, "Not run yet", "Running…", "Run failed", "Nothing found") and ends with "Add or remove documents", which opens the document picker in a sheet. A project with no documents shows the picker as the whole screen ("Use N documents"). There is no separate Documents page.
3. **Left: the document**, rendered, with highlights. Every extracted value keeps its field colour, in every record, as today. Selecting a field in the table keeps that field's highlights at full strength, in every record, and fades the other fields' highlights (a pale fill and underline, still in their colour); the document scrolls to the selected field's value in the current record. A second click on the row, or Esc, clears the selection. No label chips inside the text and no legend above it: the table is the legend, and hovering a highlight names its field. The current record is marked by a thin line in the margin of its part of the document. "Document | Output" swaps this pane to the output of this document; the output format and template settings live in the Output view. The switch is hidden while the configuration is empty.
4. **Under the document, pinned: the record strip**, "Found in this record". It shows the whole current record, one record at a time, so there is one place to read it. Its first line: previous and next record, "Record 1 of 3" (opens the list of this document's records, with "Accept all suggested"), the record's review state, Accept and Reject, and a chevron that folds the strip to this line ("Hide the record's values" / "Show the record's values"; the choice holds while the project is open, also across documents). Below it, one line per field of the record type, in the field table's order (a field with several values has one line per value, the name on the first): the field's colour dot and name, then the value (cut to two lines with "Show all") with its actions (accept, reject, correct, remove, undo). A field that is not an exact quote carries a small quiet tag "worked out" after its name. An exact-quote value that is placed in the text is a button that scrolls the document to its highlight and focuses it. A field with no value says "Not found" and has no actions. A rejected value is struck through with its state and the way back, on its own line. A quote that is not in the text has a quiet note "not in the document as written". The line of the field selected in the table is shaded like its row, and a click on a field's name in the strip selects it as a click on the row does. The strip keeps at most 45% of the screen's height and scrolls inside itself. It is not shown before a first run. Values are not listed in the right column.
5. **Acting on a value happens where it is seen.** A click on a highlight selects its record and opens that value's actions (accept, reject, correct, remove) in a small menu at the highlight; every value has the same actions on its line in the strip. Marking text by selecting it in the document keeps today's menu and rules.
6. **Right: one column**, about 560px (at least 480px; below about 1100px wide it becomes an overlay opened by a "Fields" button). From the top:
   - the record type: its name, "n fields", "Add field"; a segmented control when there are several record types;
   - "What to extract": the prompt on one line, truncated; a click edits it in place;

- "Chunking": a one-line row under it, closed by default, that says what is chosen ("Automatic", "By paragraph, 4000 characters"). The header is a button (a chevron, `aria-expanded`); open, it shows "Strategy" (Automatic, By heading, By paragraph, Fixed size) and, unless Automatic, "Size" in characters (a whole number from 1000 to 8000, 4000 to start). A wrong size shows its message in place. It is hidden with "What to extract" (no prompt and no record type), and an assistant proposal or a template never changes it;
- **the field table**, today's Define table with its controls in place: the field's colour dot and name with what to look for under it, the type, the "Exact quote" and "Several values" checkboxes, and the options menu (move, edit key, remove); the allowed values of a choice as today. A click on a row outside its controls selects the field (point 3);
- **the assistant**: a one-line input at the bottom of the column. Using it, or "Assistant" in the top bar, opens the conversation upward inside the column, oldest message first. A proposal is shown in the table: a bar "3 suggested changes · Keep all · Discard all", a new field as a row marked "New field", a changed setting or a removal as a line under the row it concerns, each later with its own Keep and Discard. A message that proposed changes keeps a one-line record ("1 kept", "Waiting for you"). "Clear conversation" is in a small menu.

7. **A new project starts empty.** The New project dialog asks for a name and a description only, and always creates the project from the blank template. With an empty configuration the right column shows "What do you want from these documents?" with a text box and the orange "Suggest fields" (it asks the assistant), "Or start from a template" with the three templates as rows, and "Or start fresh" with "Add a field yourself" (it adds a record type named "Record" with one field; the name can be changed). A template fills the list as suggestions to keep or discard.
8. **Run.** One orange button that says what happens: "Run on this document" (menu: "Run on all N documents") when this document has no results or the configuration changed since its run; "Run on all N documents" when this one is current and others are not; a secondary "Run again" when everything is current; disabled while the configuration is empty. Running saves the configuration first when it has unsaved changes. A document whose records come from an older version of the configuration shows a quiet "Configuration changed since this run". When the backend refuses a run because another is going, the screen says so.
9. **Versions.** The version text reads "Version 3", "Version 3 · unsaved changes" or "Nothing saved yet". A click opens save with a note, discard changes and the version history.
10. **Gone:** the "Ready to proceed" badge, the helper paragraphs under the prompt and above the record types, the "What to look for" column (it moves under the field name), the record cards of the Review tab (the strip and the highlights replace them), the label chips in the text, the file list column of Review and Output, the assistant's footer hint.
11. **Sizes.** It works at 1440x900 and 1280x720 with no sideways page scroll, and stacks or overlays at 390x844. The rules of `design/DESIGN.md` (Polder for apps) stay: hairlines, 4px and 6px radii, 14px Inter, 32px controls, one orange action per view, a visible focus ring, both themes.

## What does not change

The pipeline app keeps its three tabs (Define, Review, Output) and its shared components in `src/features/extraction`. The Studio gets its own screen in `src/apps/studio/`, composed from those parts. A change to a shared file is a new option whose default keeps today's behaviour.

The API does not change. Per-document state comes from each file's extraction until the backend puts it on the cell; "Suggest fields" sends the text without naming the open document; the outcome of a proposal ("1 kept") is kept on the page only.
